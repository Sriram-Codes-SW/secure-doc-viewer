## Chapter-internal issues found while checking (not AWS documentation errors)

1. **Key layout inconsistency (40.8, Listings 40.11 and 40.13, Figure 40.3).** The prose example key is `doc/v3/page-0/tile-0_0.png` and Figure 40.3 uses `doc/v-next`; the IAM policy and the lifecycle rule use the prefix `tiles/`. A lifecycle rule with `prefix = "tiles/"` would not match `doc/...` keys, and the IAM policy would not permit them. Pick one layout (for example `tiles/{documentId}/v3/page-0/tile-0_0.png`) and use it everywhere.
2. **Terraform ordering (Listing 40.13).** Provider docs for `aws_s3_bucket_lifecycle_configuration` say bucket versioning must be enabled first; add `depends_on = [aws_s3_bucket_versioning.tiles]` to the lifecycle resource.
3. **Terraform argument names and defaults (40.17): correct.** Provider `health_check` defaults are `healthy_threshold` 3, `unhealthy_threshold` 3, `interval` 30, `path` "/" (AWS API documentation: 5 and 2), as the chapter says; `matcher` sits inside `health_check`. Argument names in the listing (`block_public_acls`, `block_public_policy`, `ignore_public_acls`, `restrict_public_buckets`, `versioning_configuration { status }`, `abort_incomplete_multipart_upload { days_after_initiation }`, `noncurrent_version_expiration { noncurrent_days }`, `target_type = "ip"`) all exist.
