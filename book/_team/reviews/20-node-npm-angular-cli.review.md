## Findings

1. **minor** - Exercise format: the six exercises are in `### Exercise 20.N ★ Title` form, but they do not carry the "*Solution:* Appendix C, Exercise 20.N" line the other chapters have; the closing sentence "Solutions are in `20-node-npm-angular-cli.solutions.md`" points to the source file instead of the appendix. Use the same line as other chapters so the editor's Appendix C generation and the reader's expectations match.
2. **minor** - Terms used before defined: "compiler" and "bundler" (bundler defined inline; compiler was defined in Chapter 3 for Java), "template" (20.5 step 3: "templates are compiled (Chapter 21)"), "decorator" (`experimentalDecorators` bullet: gloss "the `@Component(...)` labels"), "source maps" (glossed), "tarball/`.tgz`" (in the lock listing: "a compressed archive"), "hash" (defined inline; Chapter 15 defines it too: keep one entry), "CORS" (defined inline in 20.6), "nginx" and "digest" (Chapter 10 pointers), "LTS" (defined inline), "static file", "pull request" (Chapter 7).
3. **minor** - Terms defined in bold here that Chapter 8 or 10 already defined (origin, proxy, digest, LTS, hash): the editor's duplicate list asks later chapters to un-bold repeated terms; keep them bold only where first defined and use plain text plus a cross-reference here.
4. **minor** - 20.2 shows sample output `v24.x.x` / `11.x.x`; fine, but 20.3 notes the project names npm 11.19.0 and warns older npm "may print warnings". State what the reader should do if their npm is older (`npm install -g npm@11` or ignore), since Node 24 ships a specific npm version.
5. **minor** - 20.5 step 4 says the dev server "listens at 4200 (the README.md in the folder says so)": the README is Angular's generated boilerplate; better to cite `angular.json`'s serve defaults or the CLI's own output. Also step 2 says the `serve` target's default configuration is `development`; verify that in `angular.json` (I did not re-grep it this window).
6. **minor** - 20.4 says `npm install # once: download everything into node_modules`, while 20.10 says the Dockerfile and CI use `npm ci`. For a reader's first install `npm ci` also works (there is a lock file) and is what Exercise 20.4 asks for; make the two consistent ("`npm ci` for an exact copy of the tested versions; `npm install` when you add or change a dependency").
7. **minor** - 20.9 "Why npm and the Angular CLI, and not the alternatives" states reasons for the project's choices ("comes with Node", "fewer tools is worth more than a speed gain"). The dossier has no recorded reasoning for choosing npm over Yarn/pnpm; the section says "None of these is 'the right answer' in general; they are reasonable defaults", which is honest, but the sentence "The project uses plain npm because it comes with Node ... and its `packageManager` field pins the version" presents inferred reasons as the project's. Reword as "reasons a team would have" or add the standard "the project records no reasoning here" sentence used elsewhere in the book (Chapter 6.9).
8. **minor** - Analogy (print shop) has its breakdown. Figure 20.1 is a sequence diagram with a bold caption above the code block; STYLE 13.1 wants the caption below in italics.
9. **minor** - Length and pacing: about 4,500 words, 12 sections; the Advanced tier (20.10 to 20.12) is compact and well linked to Chapters 10 and 36. Add a one-line reminder that Docker and CI content can be skipped on a first read if the reader only wants to run the frontend.
